## 3. 발표에서 사용할 주장 경계

### 발표에서 말할 수 있는 것

- 학생 입력과 대학 공식 공개 정보를 분리해 역할별 교수 후보와 연결 이유를 보여준다.
- 교수 선택 뒤 논문·첫 질문·이메일·면담 후 행동을 한 흐름으로 연결한다.
- 개인 고민용 첫 교수와 프로젝트 실행용 교수를 서로 다른 기준으로 연결한다.
- AI는 맞춤 질문·대화 정리·제한된 후보 재정렬을 담당한다.
- 자동 테스트 82/82, TypeScript 검사, 프로덕션 빌드를 통과했다.
- 정적 페이지 47/47, 정적·동적·API 포함 52개 라우트가 출력됐다.
- 대표 화면을 데스크톱 1440×900과 모바일 390×844에서 확인했다.

### 발표 전에 증거를 더 모아야 하는 것

- 실제 학생의 무설명 사용 장면과 원문 발언
- 첫 멈춤을 반영한 개선 전후
- 같은 과업 재테스트
- 외부 사용자 완료율·행동 변화 수치
- 운영진 공식 배점·발표 시간·Q&A·제출 형식

### 금지 표현과 교체 문장

| 사용하지 않을 표현 | 발표에서 사용할 표현 |
|---|---|
| 가장 잘 맞는 교수를 정확히 찾아준다 | 공식 근거 범위에서 서로 다른 대화 시작점을 보여준다 |
| 교수 면담을 성사시킨다 | 학생이 첫 질문과 연락을 준비하도록 돕는다 |
| 실제 사용자 효과가 입증됐다 | 제품 가설을 구현하고 내부 시나리오·브라우저 QA를 통과했다 |
| 모든 대학에 바로 확장할 수 있다 | 단국대학교 공식 공개 데이터 범위에서 파일럿을 구현했다 |
| AI가 교수 적합성과 성공을 판단한다 | AI는 질문·정리와 공식 후보 안의 제한된 재정렬을 담당한다 |

목적: 기능 소개 전에 한 학생의 막힌 장면을 고정한다.

## 6. 90초 백업 시연

인터넷·API·발표장 환경에 문제가 생기면 아래 녹화를 즉시 재생한다.

1. 0~10초 — 학생 문제 한 문장
2. 10~30초 — 교수 3인 피칭과 공식 근거
3. 30~50초 — 교수 선택→첫 질문
4. 50~68초 — AI 프로젝트 설계→맞춤 교수
5. 68~82초 — AI 교수님 대화 지도
6. 82~90초 — 테스트·빌드와 다음 사용자 검증

백업 묶음:

- 90초 MP4
- 화면 캡처 5장
- PDF 발표자료
- 오프라인 발표 대본
- 테스트 결과 캡처
- 서비스 실패 시 사용할 정적 화면

## 7. 예상 심사 Q&A 20개

### 문제·사용자

1. **이 문제가 실제 학생에게 존재하나요?**
   현재는 학생이 누구에게 무엇을 질문할지 결정하기 어렵다는 제품 가설을 멘토링과 기획 검토로 구체화했다. 실제 학생의 무설명 행동 관찰은 발표 전 남은 검증이다.

2. **핵심 사용자는 누구인가요?**
   전공은 정했지만 진로·프로젝트 방향이 막막하고 교수에게 어떤 질문을 할지 정리하기 어려운 대학생이다. 현재는 단국대학교 공식 데이터 환경의 파일럿이다.

3. **기존 해결 방식과 무엇이 다른가요?**
   검색과 범용 AI 뒤에 남는 공식 근거 확인·교수 선택·질문·이메일·면담 후 행동을 하나의 여정으로 연결한다. 기존 방식 대비 시간·성공률 비교는 아직 없다.

4. **ChatGPT나 교수 검색이면 충분하지 않나요?**
   공식 교수 사실은 대학 공개 데이터에 한정하고 AI는 질문과 생각 정리를 담당한다. 결과 카드에서 끝나지 않고 실제 대화 준비와 성장 기록까지 연결한다.

5. **교수가 바쁜데 실제 만남이 가능한가요?**
   면담 가능성이나 수락을 보장하지 않는다. 학생이 공식 정보를 확인하고 질문·이메일을 직접 검토하도록 준비하며, 연락과 최종 선택은 학생과 교수가 결정한다.

### 제품·추천

6. **가장 핵심 흐름은 무엇인가요?**
   최소 설정→공식 근거가 다른 교수 3인 비교→한 명 선택→첫 질문과 다음 행동 준비다.

7. **왜 세 명인가요?**
   1·2·3등이 아니라 가까운 시작점·주제 연결형·방법 연결형의 서로 다른 대화 역할이다.

8. **같은 학과 교수를 먼저 보여주는 것이 최선인가요?**
   가장 적합하다고 단정하지 않는다. 전공 맥락을 설명하기 상대적으로 가까운 시작점이며 연구 적합성은 별도 근거로 표시한다.

9. **추천은 어떻게 만드나요?**
   학생 입력을 구조화하고 공식 프로필의 소속·연구분야·논문과 규칙으로 대조한다. 프로젝트 AI는 공식 규칙으로 좁힌 후보 ID 밖의 교수를 선택할 수 없다.

10. **교수 데이터는 얼마나 믿을 수 있나요?**
    2026-07-27 기준 단국대학교 공식 디렉터리 115개 학과·전공, 정규화 교수 1,051명의 파일럿이다. 공식 프로필에 없는 항목은 추정하지 않고 미기재와 수집 공백을 구분한다.

11. **왜 점수와 순위를 없앴나요?**
    학생과 교수의 관계를 단일 숫자로 설명할 검증 기준이 없었다. 점수 대신 연결 이유·직접 확인할 점·첫 질문을 보여준다.

12. **왜 첫 교수와 프로젝트 교수를 분리했나요?**
    첫 연결은 전공·진로 고민의 대화 시작, 프로젝트 연결은 주제의 방법·범위·응용 전문성 탐색이 목적이기 때문이다.

13. **논문 한입은 왜 필요한가요?**
    막연한 질문 대신 교수 연구를 문제·방법·결과·한계·질문으로 가볍게 준비하는 보조 도구다. 필수 관문은 아니며 건너뛸 수 있다.

14. **AI는 어디까지 사용하나요?**
    맞춤 후속 질문·대화 요약·이어갈 질문·논문 읽기 보조를 담당한다. 교수 사실·후보 범위·면담 가능성·성공 가능성은 생성하지 않는다.

### 데이터·UX·기술

15. **개인정보와 대화 기록은 어떻게 처리하나요?**
    현재 MVP는 브라우저 로컬 저장이며 API 키는 서버 환경변수에서만 읽는다. 최근 12개 메시지만 AI 요청에 사용하고 사용자가 고른 요약만 성장 메모가 된다.

16. **AI나 데이터 조회가 실패하면 어떻게 되나요?**
    학생 입력과 선택 상태를 보존한다. AI 질문 실패 시 검수된 질문, 재정렬 실패 시 공식 규칙 결과, 논문 공백 시 직접 확인·건너뛰기로 이어간다.

17. **기능이 많아 길을 잃지 않나요?**
    홈은 미완료된 가장 앞 단계 하나를 주 행동으로 보여주고 매칭→만남, 프로젝트→추천을 묶었다. 첫 방문 안내는 한 번만 나오며 도움말로 다시 볼 수 있다.

18. **어디까지 구현·검증했나요?**
    핵심 입력·저장·복원·빈 상태와 사용자 흐름을 구현했다. 테스트 82/82, TypeScript, 프로덕션 빌드, 대표 PC·모바일 QA를 통과했다. 실제 사용자 효과 검증은 별도다.

### 평가·다음 단계

19. **가장 강한 부분과 약한 부분은 무엇인가요?**
    제품 흐름과 선택 이유 설명은 상대적으로 강하다. 실제 사용자의 멈춤·원문 발언·개선 후 재테스트가 가장 큰 공백이다. 내부 25점 환산은 공식 배점이 아니다.

20. **가장 먼저 할 다음 검증은 무엇인가요?**
    학생 한 명에게 설명 없이 핵심 과업을 수행하게 하고 첫 멈춤을 기록한다. 가장 큰 혼란 하나를 수정한 뒤 같은 과업으로 재테스트한다.
