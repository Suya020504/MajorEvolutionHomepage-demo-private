## 1. 이번 작업의 목적

서비스의 중심을 `너의 교수님은?`과 아래 핵심 3기능으로 다시 정리했다.

1. **나의 교수님 — 찾다**: 진로·관심 분야와 연결되는 교수를 공식 근거로 찾는다.
2. **전공 진화 실험실 — 만들다**: 내 전공 / 전공+AI / 전공+타 전공 프로젝트를 만든다.
3. **교수님 퀘스트 — 잇다**: 교수님을 만나기 전부터 만난 후까지 실제 행동을 돕는다.

멘토링에서 제외하기로 한 점수·순위 중심 표현과 초기 프로토타입 화면을 걷어내고, 기존 사용자가 저장한 주소는 끊기지 않도록 최신 화면으로 이동시켰다.

## 2. 적용한 제품 결정

### 교수 추천

- 추천 점수, 백분율, 순위, 가중치 합산을 제거했다.
- 결과는 `OFFICIAL_EVIDENCE_RULES_V3` 정책으로 선택한다.
- 비교 순서는 아래와 같다.
  1. 사용자가 고른 주제와 공식 연구 근거의 구체적 개념 일치
  2. 공식 학과와 학생 전공의 일치
  3. 연구 방법 개념 일치
  4. 연구 맥락 개념 일치
  5. 관련 논문·연구분야·공식 프로필 근거의 완전성
  6. 조건이 같을 때 교수 ID로 결과를 안정적으로 재현
- API 결과에는 점수 대신 `matchedConcepts`, `departmentMatchesMajor`, 근거·출처 보유 여부를 제공한다.
- 주제·방법·확장 관점의 교수 3명을 서로 다른 역할로 제공하되, 우열 순위처럼 표현하지 않는다.

### 전공 진화 후보 선택

- 로컬 후보 선택에 남아 있던 `rankScore` 가중합도 제거했다.
- 관심 연결 여부 → 방법 연결 여부 → 데이터 접근 가능 여부 → 기간 적합 여부를 차례대로 확인한다.
- 모든 근거 조건이 같을 때만 안정적인 주제 ID 순서를 사용한다.
- 크롤러의 `match_score`는 외부 논문과 교수 레코드를 같은 인물·문헌으로 연결하기 위한 데이터 정합성 값이다. 사용자 추천·우열 계산이 아니므로 이번 범위에서 유지했다.

### 구형 화면과 주소

초기 점수형 아이디어 랩, 전공 DNA, 구형 홈·탐색·보관함 화면과 사용하지 않는 상태 저장소·가상 교수 데이터를 삭제했다. 주소 파일은 아래 이동 규칙만 담당한다.

| 기존 주소 | 최신 주소 |
|---|---|
| `/mentoring`, `/goal`, `/dna`, `/analyzing`, `/home` | `/` |
| `/explore`, `/ideas`, `/ideas/compare`, `/evolution-report`, `/feasibility`, `/passport` | `/research` |
| `/saved`, `/profile` | `/portfolio` |
| `/paper` | `/paper/reader?mode=bite` |

삭제된 구형 로컬 저장 키 `major-evolution-prototype`는 사용자 브라우저에서 자동 삭제하지 않는다. 기능에는 더 이상 연결되지 않지만, 사용자 데이터의 자동 파기를 피하기 위한 결정이다.

### 논문 한입 Q01

- `/paper/reader?mode=bite`를 현재 통합 화면으로 사용한다.
- 사용자가 붙여 넣은 80~12,000자의 초록 또는 본문을 분석한다.
- 결과는 문제·방법·결과·한계·교수님께 물어볼 질문의 5개 카드다.
- 카드별 편집·복사, 전체 복사, 교수님 퀘스트 저장이 가능하다.
- 같은 결과를 다시 저장하면 기존 카드를 갱신하여 중복을 막는다.
- 근거 범위는 `사용자가 붙여 넣은 텍스트 범위 · 페이지 정보 없음`으로 고정한다.
- 미공개 논문·개인정보·연구실 내부 자료를 붙여 넣지 말라는 전송 안내를 표시한다.
- AI 연결 실패 시 임의 결과를 만들지 않고 오류를 그대로 안내한다.

PDF 원문 보기, 전체 번역, 페이지 근거 기반 자유 질의응답, 그림·표 해설은 아직 동작하지 않는다. 팀원이 만드는 PaperPal형 모듈이 준비되면 같은 화면과 `PaperReaderInsight` 계약에 교체 연결한다.

대표 주제 회귀 확인:

- 소비자 가치: 식품자원경제학과 정다은 교수 + 경제학과 박범조 교수 + 식품자원경제학과 허승욱 교수
- 식품 가격: 식품자원경제학과 양성범 교수 + 무역학과 김윤영 교수 + 경제학과 심지홍 교수
- 그린워싱·AI: 식품자원경제학과 정다은 교수 + 심리치료학과 정예슬 교수 + 식품자원경제학과 김호 교수

방법·확장 관점 교수는 주제 교수와 다른 관점을 의도하므로 학과가 넓게 분산될 수 있다. 데모 주제 20~30개로 회귀 사례를 늘리는 작업이 필요하다.

## 5. 작업 중 오류와 재발 방지

### PowerShell에서 `npm` 실행 차단

- 원인: Windows 실행 정책이 `npm.ps1`을 차단했다.
- 해결: 이 저장소의 자동 검증은 `npm.cmd`로 실행했다.
- 재발 방지: Windows PowerShell 명령 예시는 `npm.cmd run ...`을 사용한다.

### 빌드와 타입 검사 동시 실행

- 원인: Next.js가 `.next/types`를 교체하는 중 TypeScript가 같은 파일을 읽으면 경합이 발생한다.
- 해결: `build`와 `typecheck`를 순서대로 실행했다.
- 재발 방지: 두 명령을 병렬 실행하지 않는다.

### 경로에 공백이 있는 로컬 서버 실행

- 원인: Node 실행 파일 경로를 직접 전달할 때 공백 인수가 분리되어 첫 실행이 종료됐다.
- 해결: `npm.cmd`를 숨김 프로세스로 직접 실행했다.
- 재발 방지: Windows에서는 경로가 긴 실행 스크립트보다 프로젝트 작업 폴더를 지정한 `npm.cmd start`를 사용한다.

## 6. 남은 위험과 다음 작업

1. `npm audit` 기준 Next.js 15.5.19와 간접 의존성 `sharp`에 높은 등급 취약점이 있다. 패키지 변경 승인을 받은 뒤 Next.js 15.5.21 이상으로 올리고 타입 검사·빌드·브라우저 회귀를 다시 실행한다.
2. 논문 한입 실생성에는 서버 전용 `OPENAI_API_KEY`가 필요하다.
3. PDF·번역·근거 Q&A·그림 해설은 팀원 PaperPal 모듈 연결 전까지 후속 기능이다.
4. 교수 추천 회귀 검증은 현재 대표 주제 3개다. 단국대 주요 계열별 데모 주제를 추가해야 한다.
5. 대안 교수의 학과 분산이 사용자 기대보다 넓을 수 있어, `다른 관점`의 허용 범위를 제품 문구와 회귀 사례로 합의해야 한다.
6. 교수 강의시간표는 공식 갱신 주기·비공개 범위를 먼저 정한 뒤 별도 데이터 계약으로 추가해야 한다.
7. 인증, 여러 기기 동기화, AI API 비용 제한은 아직 없다. 공개 배포 전 요청 제한과 사용량 보호가 필요하다.
8. 구형 로컬 저장 키는 고아 데이터로 남는다. 팀 합의 후 사용자가 직접 지울 수 있는 설정 기능을 추가할 수 있다.
9. 360px·430px·1440px 전체 라우트 회귀와 자동 E2E는 PR 전에 한 번 더 실행한다.

## 7. 팀원 인계 순서

1. 이 브랜치를 받아 `.env.local`에 서버 키를 설정한다.
2. `npm.cmd run typecheck` → 교수 검증 2종 → `npm.cmd run build` 순서로 실행한다.
3. `/`, `/professors`, `/research`, `/quest`, `/paper/reader?mode=bite`, `/portfolio`를 우선 검토한다.
4. 제품 결정에 동의하면 원 코드베이스로 PR을 올린다.
5. PaperPal 모듈 담당자는 `docs/PAPER_READER_HANDOFF.md`의 계약을 기준으로 Q01 화면 내부를 단계적으로 교체한다.
